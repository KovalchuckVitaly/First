# Короткие ответы

## 1. Что такое процесс?

Процесс — запущенный экземпляр программы.

Программа представляет собой исполняемый код, а процесс — его выполняющийся экземпляр со своим PID, состоянием и ресурсами.

---

## 2. PID и PPID

```text
PID  → Process ID
PPID → Parent Process ID
```

PPID содержит PID родительского процесса.

---

## 3. fork() и execve()

Упрощённо:

```text
Bash
 ↓
fork()
 ↓
Child
 ↓
execve()
 ↓
Program
```

`fork()` создаёт дочерний процесс.

`execve()` заменяет выполняемую программу процесса новой.

---

## 4. Состояния

```text
R → Running / Runnable
S → Interruptible Sleep
D → Uninterruptible Sleep
T → Stopped
Z → Zombie
```

---

## 5. R

`R` означает, что процесс выполняется **или готов к выполнению**.

Поэтому процесс в `R` не обязательно физически выполняется на CPU именно сейчас.

---

## 6. S и D

`S` — прерываемое ожидание.

`D` — непрерываемое ожидание операции ядра, часто связанной с I/O.

Пока процесс остаётся в `D`, даже `SIGKILL` не сможет завершить его немедленно.

При длительном `D` необходимо искать причину ожидания: storage, filesystem, NFS, kernel/I/O errors и т.д.

---

## 7. Zombie

Zombie — уже завершившийся Child, для которого Parent ещё не забрал exit status.

Правильное направление:

```text
Child завершается
       ↓
ядро сохраняет exit status
       ↓
Zombie
       ↓
PARENT вызывает wait()/waitpid()
       ↓
Parent получает exit status
       ↓
Zombie удаляется
```

**Parent вызывает `wait()` / `waitpid()`.**

`kill -9` не поможет, потому что процесс уже завершён.

---

## 8. Много Zombie

Одинаковый PPID у большого количества Zombie указывает на общего Parent, который необходимо расследовать.

Нельзя автоматически завершать Parent на production.

Сначала необходимо выяснить:

- что это за процесс;
- почему он не забирает exit status;
- насколько он критичен;
- можно ли безопасно его перезапустить.

---

## 9. Zombie vs Orphan

```text
Zombie
→ уже завершён

Orphan
→ ещё работает,
  но первоначальный Parent завершился
```

Живой orphan будет reparented.

---

## 10. Ctrl+Z

Обычно:

```text
Ctrl+Z → SIGTSTP
```

Не `SIGSTOP`.

`SIGTSTP` можно обработать или проигнорировать.

`SIGSTOP` нельзя обработать, проигнорировать или заблокировать.

---

## 11. bg и fg

```bash
bg %1
```

продолжает job №1 в background.

```bash
fg %1
```

переводит job №1 в foreground.

Новый процесс при этом не создаётся, поэтому PID не меняется.

---

## 12. Job ID и PID

```text
[1] 5000
```

означает:

```text
1    → Job ID текущего Bash
5000 → PID процесса
```

---

## 13. jobs и ps

`jobs` показывает jobs текущего Bash.

`ps` показывает информацию о процессах Linux в зависимости от заданных параметров.

Поэтому процесс может существовать, но отсутствовать в `jobs`.

---

## 14. kill

`kill` — команда для отправки сигналов.

Например:

```bash
kill -SIGSTOP 5000
```

не завершает процесс, а останавливает его.

Поэтому:

```text
kill → send signal
```

---

## 15. SIGTERM и SIGKILL

```text
SIGTERM
→ запрос на завершение
→ приложение может обработать/игнорировать
→ позволяет выполнить graceful shutdown
```

```text
SIGKILL
→ принудительное завершение
→ нельзя обработать/игнорировать/заблокировать
→ application-level cleanup невозможен
```

Обычно сначала используется `SIGTERM`.

---

## 16. kill / pkill / killall

```text
kill PID
→ сигнал конкретному PID

pkill criteria
→ поиск процессов по критериям + сигнал

killall name
→ сигнал процессам с указанным именем
```

---

## 17. Scheduler

Scheduler распределяет CPU между runnable-задачами.

Если доступен один CPU, восемь CPU-bound процессов не могут физически выполняться на нём одновременно.

Scheduler переключает выполнение между ними.

---

## 18. nice

```text
-20 → высокий CPU priority
0   → стандартный
19  → низкий CPU priority
```

`nice` влияет на относительное распределение CPU при конкуренции.

`nice` не является CPU limit.

---

## 19. nice=19 без конкурентов

Да.

Если CPU никому больше не нужен, CPU-bound процесс с:

```text
nice=19
```

может использовать практически 100% одного CPU.

---

## 20. nice и renice

```bash
nice -n 10 command
```

запускает новый процесс с указанным nice.

```bash
renice 10 -p PID
```

изменяет nice уже существующего процесса.

Обычному пользователю нельзя произвольно повышать CPU priority своих процессов.

---

## 21. nohup

```bash
nohup ./backup.sh &
```

содержит два разных механизма:

```text
nohup → программа игнорирует SIGHUP

& → программа запускается в background
```

---

## 22. disown

`disown` относится к Bash Job Control.

```bash
disown %1
```

убирает существующий job из управления текущего Bash.

Процесс при этом может продолжать существовать.

---

## 23. Parent и SIGHUP

Смерть Parent сама по себе не означает автоматическую отправку `SIGHUP` всем его Child.

Если живой Child потерял первоначального Parent:

```text
Parent terminates
       ↓
Orphan
       ↓
Reparenting
       ↓
New Parent
```

---

## 24. cat &

Background process group, пытающаяся читать из управляющего терминала, может получить:

```text
SIGTTIN
```

и остановиться.

Поэтому:

```bash
cat &
```

может перейти в `Stopped`.

---

## 25. Поиск процесса

Найти PID:

```bash
# Ищет процессы nginx и выводит PID.
pgrep nginx
```

Посмотреть конкретный процесс:

```bash
# Показывает PID, PPID, состояние и команду процесса.
ps -p 5000 -o pid,ppid,stat,cmd
```
