# Module 01 — Linux Filesystem

## 1. Что такое файловая система

Файловая система — это механизм, с помощью которого операционная система организует хранение файлов и каталогов на устройстве.

Файловая система определяет:

- как хранятся данные;
- как файлы получают имена;
- как организуются каталоги;
- как хранятся владельцы и права доступа;
- как операционная система находит содержимое файла;
- как отслеживается свободное и занятое место.

Примеры файловых систем Linux:

- ext4;
- XFS;
- Btrfs;
- tmpfs.

## 2. Корневой каталог

В Linux существует единое дерево каталогов.

Самая верхняя точка этого дерева называется корневым каталогом:

```
/
```

Примеры абсолютных путей:

```
/etc/passwd
/home/vital/file.txt
/var/log/syslog
```

Даже если в системе используется несколько дисков, они подключаются к определённым каталогам единого дерева файловой системы.

## 3. Абсолютные и относительные пути

### Абсолютный путь

Абсолютный путь начинается с `/` и описывает полный путь от корня файловой системы.

Пример:

```
/home/vital/documents/report.txt
```

Такой путь не зависит от текущего рабочего каталога.

### Относительный путь

Относительный путь отсчитывается от текущего рабочего каталога.

Пример:

```
documents/report.txt
```

Результат зависит от того, в каком каталоге находится пользователь.

## 4. Специальные обозначения путей

### `/`

Корневой каталог всей файловой системы.

### `.`

Текущий каталог.

Пример:

```
# Запускает script.sh из текущего каталога.
./script.sh
```

### `..`

Родительский каталог.

Пример:

```
# Переходит на один уровень выше относительно текущего каталога.
cd ..
```

### `~`

Домашний каталог текущего пользователя.

Пример:

```
# Переходит в домашний каталог текущего пользователя.
cd ~

## 5. Текущий рабочий каталог

Каждый процесс имеет текущий рабочий каталог, также называемый current working directory или CWD.

Когда Bash запускает команду с относительным путём, этот путь разрешается относительно текущего рабочего каталога Bash.

# Показывает абсолютный путь текущего рабочего каталога.
pwd
```

## 6. Что такое inode

Inode — это структура данных файловой системы, содержащая метаданные объекта.

В inode обычно хранятся:
- группа;
- права доступа;
- размер;
- временные метки;
- количество жёстких ссылок;
- указатели на блоки с содержимым файла.

В inode не хранится обычное имя файла.

Имя файла хранится в каталоге.

```
имя файла → номер inode

## 7. Каталог как таблица имён

Каталог — это специальный объект файловой системы.

Он хранит записи, связывающие имена с inode:

```
file1.txt → inode 100
file2.txt → inode 101
docs      → inode 102
```

Поэтому имя файла и сам файл — не одно и то же.

Имя является записью в каталоге, которая указывает на inode.

## 8. Hard link

Hard link, или жёсткая ссылка, — это дополнительное имя для того же inode.

Например:

```
original.txt → inode 500
hardlink.txt → inode 500
```

Оба имени указывают на один объект файловой системы.

Особенности hard link:

- оба имени равноправны;
- содержимое у них общее;
- изменения через одно имя видны через другое;
- удаление одного имени не удаляет данные, пока остаётся другая ссылка;
- жёсткие ссылки обычно нельзя создавать на каталоги;
- жёсткая ссылка не может пересекать границу файловых систем.

Создание hard link:

```
# Создаёт новое имя hardlink.txt, указывающее на тот же inode,
# что и original.txt.
ln original.txt hardlink.txt
```

Проверка inode:

```
# Опция -i показывает номер inode каждого файла.
ls -li original.txt hardlink.txt
```

## 9. Symbolic link

Symbolic link, или символическая ссылка, — это отдельный специальный файл, содержащий путь к другому объекту.

Упрощённо:

```
link.txt → "/home/vital/original.txt"
```

Символическая ссылка имеет собственный inode.

Создание:

```
# Создаёт символическую ссылку link.txt,
# которая хранит путь к original.txt.
ln -s original.txt link.txt
```

Особенности symbolic link:

- имеет собственный inode;
- может указывать на файл или каталог;
- может пересекать границы файловых систем;
- может указывать на несуществующий объект;
- становится битой ссылкой, если целевой путь исчезнет.

## 10. Разница между hard link и symbolic link

| Свойство | Hard link | Symbolic link |

| Указывает на | inode | путь |
| Собственный inode | Нет, используется inode файла | Да |
| Может пересекать файловые системы | Нет | Да |
| Может указывать на каталог | Обычно нет | Да |
| Работает после удаления исходного имени | Да | Нет |
| Может быть битой | Нет | Да |

## 11. Что делает rm

Команда `rm` не стирает содержимое файла напрямую.

Она удаляет запись имени из каталога и уменьшает счётчик жёстких ссылок inode.

Упрощённо:

```
file.txt → inode 100
```

После:

```
# Удаляет имя file.txt из текущего каталога.
rm file.txt
```

запись имени исчезает.

Данные могут быть освобождены файловой системой, когда одновременно выполняются два условия:

1. количество жёстких ссылок равно нулю;
2. ни один процесс не держит файл открытым.

## 12. Удалённый, но открытый файл

Процесс может продолжать работать с файлом даже после удаления его имени.

Причина: процесс имеет открытый файловый дескриптор, который продолжает ссылаться на открытый объект файла в ядре.

В такой ситуации:

- имя файла уже отсутствует в каталоге;
- открыть его по старому пути нельзя;
- процесс всё ещё может читать или записывать данные;
- дисковое пространство не освобождается до закрытия файла.

Найти такие файлы можно командой:

```bash
# Показывает открытые файлы, количество жёстких ссылок которых меньше 1.
# Такие файлы обычно уже удалены из каталогов, но ещё удерживаются процессами.
sudo lsof +L1
```

## 13. Файловый дескриптор

Файловый дескриптор — это числовой идентификатор открытого ресурса внутри процесса.

Например:

```text
0 — stdin
1 — stdout
2 — stderr
3 — открытый файл
4 — сетевой сокет
```

Файловый дескриптор не является именем файла.

Это ссылка процесса на открытый объект в ядре.

## 14. Как работает cp

Команда `cp` обычно создаёт новый файл:

- создаётся новая запись в каталоге;
- создаётся новый inode;
- содержимое исходного файла копируется в новые блоки;
- новый файл становится независимым объектом.

Пример:

```bash
# Копирует содержимое source.txt в новый файл copy.txt.
cp source.txt copy.txt
```

У `source.txt` и `copy.txt` будут разные inode.

## 15. Как работает mv

Поведение `mv` зависит от расположения источника и назначения.

### Перемещение внутри одной файловой системы

Обычно изменяется только запись в каталоге:

- данные не копируются;
- inode остаётся прежним;
- операция выполняется быстро.

```bash
# Перемещает файл в другой каталог в пределах файловой системы.
mv file.txt /tmp/file.txt
```

### Перемещение между разными файловыми системами

Операция становится похожей на:

1. копирование файла в новую файловую систему;
2. удаление исходного имени.

В новом месте создаётся новый inode.

## 16. Почему hard link нельзя создать между файловыми системами

Номер inode имеет смысл только внутри конкретной файловой системы.

Другая файловая система имеет собственную таблицу inode.

Поэтому запись каталога одной файловой системы не может напрямую указывать на inode другой файловой системы.

Символическая ссылка может это делать, потому что она хранит путь, а не прямую ссылку на inode.

## 17. Изменение файла и замена файла

Эти операции могут выглядеть одинаково для пользователя, но отличаются внутренне.

### Изменение содержимого существующего файла

Inode обычно остаётся прежним, а данные обновляются.

### Создание нового файла и переименование поверх старого

Может появиться новый inode, даже если итоговое имя осталось прежним.

Это важно при работе с:

- редакторами;
- конфигурационными файлами;
- hard links;
- программами, которые продолжают держать старый файл открытым.

## 18. Основная модель файла в Linux

Упрощённая цепочка выглядит так:

```text
Имя в каталоге
       ↓
     inode
       ↓
Блоки с данными
```

Для открытого файла:

```text
Процесс
   ↓
Файловый дескриптор
   ↓
Открытый объект файла в ядре
   ↓
inode
   ↓
Данные
```

Эта модель помогает понять:

- работу hard links;
- работу symbolic links;
- поведение `rm`;
- удалённые, но открытые файлы;
- различия `cp` и `mv`;
- освобождение дискового пространства.report.txt → inode 12345
```
