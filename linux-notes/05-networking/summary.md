## 1. Что нужно помнить

| Понятие | Главное |
|---|---|
| IP | Адресация и маршрутизация на L3 |
| MAC | Адресация Ethernet-кадров на L2 |
| ARP | Поиск MAC следующего узла по IPv4 |
| TCP | Соединение: SYN → SYN-ACK → ACK |
| UDP | Датаграммы без TCP Handshake |
| Gateway | Следующий маршрутизатор для внешних сетей |
| DNS | Преобразование имён в адреса |
| `127.0.0.1` | Loopback — сам узел |
| `0.0.0.0` при bind | Все локальные IPv4-адреса **сервера**, не вся подсеть |

## 2. Основные команды

```bash
ip -br addr
# Кратко показывает интерфейсы и IP.

ip -br link
# Кратко показывает состояние интерфейсов.

ip route show
# Показывает таблицу маршрутизации.

ip route get 8.8.8.8
# Показывает выбранный маршрут к указанному IP.

ip neigh show
# Показывает таблицу соседей / ARP.

ping -c 4 192.168.20.50
# Отправляет четыре ICMP-запроса к хосту.

sudo ss -lntp
# Показывает слушающие TCP-сокеты и процессы.

sudo ss -lntp 'sport = :8080'
# Фильтрует локальные слушающие TCP-сокеты по порту 8080.

curl -v http://127.0.0.1:8080/health
# Подробная HTTP-проверка приложения.

cat /etc/resolv.conf
# Показывает настройки DNS-резолвера.

getent hosts api.example.com
# Проверяет системное разрешение имени через NSS.

dig api.example.com
# Выполняет DNS-запрос.

dig @8.8.8.8 api.example.com
# DNS-запрос к конкретному серверу.

sudo firewall-cmd --get-active-zones
# Показывает активные зоны и их интерфейсы / источники.

sudo firewall-cmd --zone=public --list-all
# Показывает конфигурацию зоны public.

sudo firewall-cmd --zone=public --query-port=8080/tcp
# Проверяет порт 8080/tcp в зоне public.

sudo firewall-cmd --permanent --zone=public --add-port=8080/tcp
# Сохраняет разрешение TCP-порта в постоянной конфигурации зоны.

sudo firewall-cmd --reload
# Применяет постоянную конфигурацию без перезагрузки Linux.
```

## 3. Дополнительные инструменты (синтаксис можно подсматривать)

```bash
nc -zv -w 3 192.168.20.50 8080
# Проверяет TCP-подключение к удалённому IP и порту.

resolvectl status
# Показывает DNS-конфигурацию на системах с systemd-resolved.

sudo tcpdump -ni ens33 'host 192.168.10.25 and tcp port 8080'
# Наблюдает TCP-пакеты на интерфейсе; продвинутая диагностика.
```

## 4. Характерные ошибки

| Симптом | Что можно утверждать |
|---|---|
| `ip neigh ... FAILED` | Не удалось разрешить / проверить соседа |
| `curl: (6) Could not resolve host` | Имя не разрешено |
| DNS `NXDOMAIN` | Получен ответ о несуществующем имени |
| DNS `timed out` | Не получен DNS-ответ вовремя |
| `Connection refused` | TCP-подключение отвергнуто |
| `Connection timed out` | TCP-подключение не установилось вовремя |
| `Connected` и HTTP `500` | TCP успешен, приложение вернуло HTTP-ошибку |
| HTTP `502` | Reverse proxy / upstream взаимодействуют некорректно |

## 5. Типичные ошибки мышления

1. **`0.0.0.0` — все IP локальной подсети.** Нет, это все локальные IPv4-адреса **сервера**.
2. **Сокет слушает IP клиента.** Нет, адрес прослушивания — локальный IP **назначения**.
3. **`ip route get` подтверждает доставку.** Нет, он показывает выбор маршрута ядром.
4. **Ping работает, значит TCP-порт открыт.** Нет: ICMP и TCP — разные протоколы.
5. **`ss` показывает LISTEN, значит удалённый клиент точно подключится.** Нет: есть ещё маршрутизация и firewall.
6. **Асимметричная маршрутизация всегда неправильная.** Нет: она может быть допустимой.
7. **Подозрительное обстоятельство — доказанная причина.** Нет: проверяем гипотезу.
8. **Команда firewall вернула `success`, проблема решена.** Нет: повторяем исходный запрос клиента.

## 6. Короткий план диагностики

**Не работает сервис по IP и порту:** `ss` → `ip -br addr` → `ip route get` → зоны `firewall-cmd` → `curl` и журналы приложения.

**Не работает по домену:** `getent` / `dig` → настройки DNS → запрос к альтернативному DNS-серверу.

**TCP работает, но HTTP 500:** проверить журналы и зависимости приложения.

**После исправления:** снова воспроизвести исходный запрос, подтвердить восстановление.

## 7. Что повторять позднее

- `127.0.0.1`, конкретный IP и `0.0.0.0` при прослушивании.
- IP-адрес источника и назначения, маршрут ответных пакетов.
- Назначение и синтаксис `nc`.
- Зоны `firewalld`, `--permanent`, `--reload`.
- Разделение гипотезы и подтверждённой причины.
- При Docker/Kubernetes: DNS, TCP-порты, loopback, маршруты и firewall.

> **Diagnose → Hypothesis → Verify Root Cause → Minimal Fix → Recheck.**
